### C50 — should-fix — `scripts/migrate.mjs:128`, `:82`, `:169`, `:187`

A line comment ends at a line feed for the guard and at a line feed or a carriage return for the server: what follows a lone CR on a comment's line is run and never read. `scripts/format-check.mjs:21` refuses any CR in a tracked `.sql`, which holds the tree today; `migrate.mjs` does not rely on it. Reproduced on PostgreSQL 17.11: `-- a note␍truncate public.victim;` (0 rows after), the same before `set/**/schema` in a body (the table moved), `drop table`, a type change and `do E'…dr\157p…'` (each ran). Suggested fix: refuse a file holding a CR not followed by LF, or end a line comment at `\r` in the four places; add the five statements to the tests.

### C51 — should-fix — `scripts/check-workflows.mjs:200-232`, `:186`

A `runs-on` key folded over two lines in a double-quoted explicit key (`? "runs-\` / `on"` / `: nas`) is read by nothing, and the job's one accepted `runs-on` line can sit inside a scalar or flow mapping continued at the job's indent; `js-yaml` 4.3.2 reads `runs-on: nas`. Not verified that GitHub's reader accepts it. Suggested fix: at a job's indent accept only `<plain-key>:` lines; refuse a line ending with a backslash outside a `run:` block, and any `?` key.
