## New findings

### C30 — should-fix — `scripts/migrate.mjs:138`, `:141`, `:142`, `:144` (the rules), `:116-123` (a body is kept raw), `:106-115` (`U&"…"`)

Four of the five contracting rules are passed by a comment glued to a keyword inside a dollar-quoted body, and the type-change rule by a column written `U&"…"`.

- **Why**: the rules ask for white space after the keyword (`drop\s+`, `set\s+schema`, `…\s+type`). Outside a body the lexer turns a comment into a space. Inside a body it keeps the text raw, so `drop/**/table` has no white space to match. The header says the opposite.
- **Truncate**: the exemption for a trigger's event looks behind for `before|after|or|of` and white space. A line comment that ends with one of those words, right before `truncate` in a body, satisfies it.
- **`U&"c"`**: the lexer emits `U&"_"`, and the rule's column name is a word or a quoted name followed by white space, so it does not match.
- **Reproduction** (NAS, PostgreSQL 17.11; each gives `contracting() = null` and `planMigrations: planned`):

  | Statement | After it ran |
  |---|---|
  | `do $$ begin drop/**/table public.victim; end $$;` | table gone |
  | `do $$ begin drop--⏎ table public.victim; end $$;` | table gone |
  | `do $$ begin alter table public.victim drop/**/column c; end $$;` | column `c` gone |
  | `create function public.f() returns void language sql as $$ drop/**/table public.victim $$; select public.f();` | table gone |
  | `do $$ begin⏎ -- the rows we no longer think of⏎ truncate public.victim;⏎end $$;` | 0 rows |
  | the same in a `plpgsql` function, comment ending in `before`, then called | 0 rows |
  | `do $$ begin alter table public.victim set/**/schema attic; end $$;` | table is `attic.victim` |
  | `do $$ begin alter table public.victim alter column c/**/type integer using 0; end $$;` | `c` is `integer` |
  | `alter table public.victim alter U&"c" type integer using 0;` | `c` is `integer` |
  | `alter table public.victim alter column U&"\0063" set data type integer using 0;` | `c` is `integer` |

- **Suggested fix**: apply the contracting rules to a copy of each body with its comments turned into a space, as the lexer does outside. Let the truncate exemption apply only to a statement's own text when it begins with `create trigger`. Have the lexer reduce `U&"…"` to `"_"`. Add the ten statements to `test/unit/migrations.test.js`.
