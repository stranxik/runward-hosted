## Findings

- **C55, should fix, corrected** (`runward/runbook.md`, section 11): "settled by hand as `rw_admin` or `rw_owner`" was false for `rw_admin`, which cannot open a session on the service database. A table or schema `revoke` needs that session; the path is a change to `db/grants.sql`, applied by `migrate` as `rw_owner`, and a redeploy. The runbook now says so.
- **C56, note, corrected** (`runward/execution-topology.md`, row of the deploy chain): it listed `roles`, `migrate` and `isolation`; `grants` is added.
- **C57, hypothesis, accepted**: the first comparison at the hoster is unobserved. It will connect and read (`migrate` answered 200 on the same URL in both stopped runs; every function and catalog it reads needs no privilege and does not depend on who asks; run 42930736032 already showed both CONNECT lines matching). Unknown: whether the hoster's `readonly` preset or default privileges reach tables created by `rw_owner` in `rw`. If they do, `grants` answers 500 with "N more", the deploy stops before the switch and rolls back (the path proven by run 43018993884), and the cure is a `revoke` in `db/grants.sql` (C55).
- **C58, note**: the hoster runs PostgreSQL 16 (`infra/scaleway/main.tf`), the CI `postgres:17`; the branch of `scripts/grants.mjs` without MAINTAIN runs only in production. Low risk (one array element; the snapshot has no MAINTAIN line). A PostgreSQL 16 leg for `test:pg` is a follow-up.
- **C59, note, follow-up**: `has_*_privilege` follows inherited memberships only; on PostgreSQL 16 a membership granted `WITH INHERIT FALSE, SET TRUE` to `rw_app` or `rw_maint` would let it `SET ROLE` without showing in the comparison. Not introduced by this change. Follow-up: refuse any `pg_auth_members` row whose member is `rw_app` or `rw_maint` (cluster-wide, readable by all).
- **C60, note, follow-up**: `scripts/grants.mjs` succeeds by exit 0; if its main guard ever mismatched (a symlinked directory, a space in the path), it would exit 0 without comparing. Not the case in the image (`/app`, where `migrate.mjs` runs with the same pattern). Follow-up: the gateway requires the gesture's success line, or the script exits non-zero when it is not main.
